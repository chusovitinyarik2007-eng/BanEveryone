# AUTO: настраиваемые балансировщики и поддержка Happ/Incy

Проект основан на исходном «Архив(5).zip». Обновлены `smart_routing.py`, `tgbot.py`,
`auto_rule_input.py`, `main.py`. Добавлены `routing_balancers.py`,
`subscription_clients.py` и тесты. Исходные настройки пулов, DNS панели,
правила DIRECT/BLOCK и привязки к ID инбаундов сохранены.

## Перед обновлением

1. **Остановите веб-сервис и служебный Telegram-бот.**
2. Скопируйте рабочую базу: `cp /opt/BanEveryone/subserver.db /opt/BanEveryone/subserver.db.bak-$(date +%F-%H%M%S)`
   (измените путь, если в `.env` задан `DB_PATH`).
3. Замените Python-файлы из архива; **рабочую SQLite и `.env` не заменяйте**.
4. Установите те же зависимости из `requirements.txt`, что используются вашим сервисом.
5. Перезапустите веб-сервис и бота; откройте `/auto` в служебном боте.
6. Обновите подписку в Happ/Incy и проверьте JSON маршрутизацию и лог Xray.

Данные SQLite не вложены в выдаваемый ZIP, чтобы случайно не стереть вашу рабочую базу.

## Telegram — управление

`/auto` → **Балансировщики** → нужный пул. Доступно:

- Добавить балансировщик для обычных серверов или для резерва `--rest`.
- Выбрать инбаунды панели (назначения сохраняются как `inbound:<ID>`).
- Задать доменные и IP-правила из нескольких Telegram-сообщений; закончить через `/done` или кнопку «Сохранить все части».
  Например `domain:gemini.google.com`, `geosite:google`, `regexp:...`, `ip:192.0.2.0/24`, `geoip:private`.
- Выбрать стратегию `leastPing`, `leastLoad`, `roundRobin`, `random`.
- Настроить `fallback`: другой балансировщик, `DIRECT` либо `BLOCK`.
- Переименовать, приоритизировать, включать/выключать, назначить пул для остального трафика.
- Удалить пользовательский пул (встроенные 4 можно отключить).
- В `/auto` изменить **общий** интервал наблюдения (`10s` … `1h`).

Правила применяются по возрастанию числового приоритета. Правила самого 3x-ui
`DIRECT/BLOCK` идут **перед всеми пользовательскими правилами**, в том числе
при повторном роутинге после fallback. Следом RU-сайты идут в DIRECT.
Балансировщик, отмеченный как основной для остального трафика, получает
последнее правило без ограничений.

Создание fallback-цикла (A → B → A) отклоняется. Если пул недоступен, цепочка
переходит к следующей доступной ступени либо в `BLOCK`; резерв не появится у
пользователей без `--rest`. При отсутствии наблюдаемых работоспособных узлов
поведение fallback определяется Xray-core и выбранной стратегией.

**Ограничение Xray:** `observatory.probeInterval` задаётся для всех выбранных
узлов профиля AUTO сразу, а не индивидуально для каждого балансировщика.
`leastPing` и `leastLoad` требуют наблюдений. Частые проверки могут увеличить
нагрузку на серверы и трафик клиента.

## Миграция существующей базы

При первом обращении к AUTO автоматически создаётся **новая** таблица
`smart_balancers`. Данные `smart_nodes`, `smart_options`, `smart_aliases`,
`smart_endpoint_map` не удаляются и не пересоздаются. Исторические назначения
`ru` переводятся в `all` по прежнему миграционному правилу, если раньше не
были перенесены. Из прежних параметров создаются четыре записи:

- Gemini → Все серверы;
- Все сайты → Все серверы (правило по умолчанию);
- Все серверы → Антиглушилка;
- Антиглушилка → BLOCK.

Уже сохранённые списки сайтов и состояние включения переносятся. Процесс
повторного запуска идемпотентен. Новые данные нужно резервировать вместе с БД.

## Почему в браузере иногда был JSON

Раньше `is_browser()` сначала проверял `X-HWID`, а также мог доверять
`User-Agent: Happ`; встроенный браузер ошибочно попадал в режим выдачи
подписки. Теперь **запрос HTML-навигации всегда получает страницу**, даже
если унаследовал заголовки Happ. Программа распознаёт Happ и Incy по
`User-Agent` или `X-Client`; остальные клиенты получают HTTP 403 и фразу
«Клиент не поддерживается. Используйте Happ или Incy.». Их запросы не
регистрируют новое устройство.

Гарантированная ссылка на HTML, если встроенный браузер необычно формирует
заголовки: `https://example.com/<sub>/<uuid>?view=web`.
Этот параметр **не используйте** как ссылку для импорта в VPN-приложение.

**Ограничение:** User-Agent можно подменить. Такая фильтрация не является
механизмом авторизации и не заменяет UUID, привязку к HWID, TLS и лимиты.
Happ может позволять менять User-Agent; если пользователь подменил его на
неизвестный, подписка будет отклонена. Incy использует `INCY/<version>/<platform>`
и `x-client: INCY` согласно официальной документации.

Для **всех** ответов сервер отправляет `Cache-Control: private, no-store`,
`Surrogate-Control: no-store` и `Vary`; они помогают не смешивать ответ HTML
и JSON в кэшах. **Но если Beget CDN или другой edge игнорирует заголовки,
необходимо дополнительно отключить кеширование URL подписок в самом CDN.**
Не смешивайте HTML/JSON для одного URL в принудительном edge-кеше.

## Проверки

Из директории проекта:

```bash
python -m compileall -q main.py smart_routing.py routing_balancers.py subscription_clients.py tgbot.py auto_rule_input.py
python -m unittest discover -s tests -v
```

Локальные тесты проверяют синтетические профили, миграцию SQLite, динамические
балансировщики, циклы, проверку клиентов, исходные пуловые назначения и
приоритет глобальных правил. **Нет live-теста с настоящим Telegram, 3x-ui,
Beget или Happ/Incy; перед боевым вводом обязательно проверьте один клиентский
профиль, включая fallback.**
