# Веб-панель AUTO / Telegram Login

## Что изменено

- Путь **`/<SUB>/adm`** (`/get-info-api/adm`, если `SUB=get-info-api`). Объявлен **перед** `/<SUB>/{uuid}`: административный адрес никогда не становится UUID подписки.
- Создание, переименование, включение, удаление (только пользовательских) балансировщиков, выбор стратегии, исходных серверов, приоритета, правил, fallback DIRECT/BLOCK/другой пул, назначение основного маршрута, разделение main/`--rest`.
- Общая частота опроса Xray 10 секунд–1 час. Глобальное включение AUTO, имя AUTO, исторические RU→DIRECT правила сохранены и доступны через отдельный сворачиваемый раздел веб-панели.
- В боте больше нет отдельных кнопок «📝 RU-сайты» и «📝 Gemini» в главном меню `/auto`; правила Gemini находятся внутри его балансировщика. Приоритет можно изменить **в обе стороны** или ввести вручную. **Меньшее число означает более раннюю проверку правил**. Глобальные правила DIRECT/BLOCK панели, а затем RU→DIRECT по-прежнему проверяются раньше правил балансировщиков.
- Старая SQLite сохраняется, схема `smart_balancers` и привязки инбаундов не удаляются. При старте автоматически добавляются только две таблицы: `admin_web_challenges`, `admin_web_sessions`.

## Авторизация

1. Откройте `https://ВАШ-ДОМЕН/get-info-api/adm`.
2. Нажмите **«Авторизоваться через Telegram»**; на странице появятся шестизначный код и ссылка в служебный Telegram-бот.
3. В **личном чате** с ботом, используя аккаунт, чей **числовой Telegram ID** перечислен в `ADMINS`, откройте deep-link `/start adm_...`.
4. Сверьте шестизначный код в Telegram и в браузере; нажмите **«Подтвердить вход»**. Если запрос не ваш — **«Отклонить»**.
5. Вернитесь в браузер. Страница автоматически получит сессию. Вход действителен **ровно 6 часов с момента подтверждения**; активность не продлевает срок.
6. **«Выйти»** немедленно удаляет сессию из SQLite и cookie браузера.

**Не изменяйте** значение `ADMINS` на username. Нужно, например, `ADMINS=12345678,98765432`. Используется уже существующий `BOT_TOKEN` служебного бота. В меню `/auto` добавлена кнопка «🌐 Веб-панель AUTO»; при необходимости укажите `ADMIN_PUBLIC_URL=https://ваш-домен/get-info-api/adm` в `.env`, чтобы бот присылал корректную ссылку. Никакие пароли, бот-токены и UUID пользователей не передаются в HTML/JavaScript панели.

Ограничения: заявка живёт 3 минуты, одноразовая, привязана к конкретному браузеру закрытым `HttpOnly` cookie. Заявка, открытая в другом браузере, **не даёт доступ**, даже после одобрения. Пользователь без ID в `ADMINS` не может подтвердить заявку. Максимум 25 попыток создания заявки за 10 минут с одного IP, отсчитываемого непосредственно от web-сокета. В течение срока сессии каждый запрос снова проверяет, есть ли ID в актуальном `ADMINS`.

## Безопасная публикация через Nginx

**Вход работает через HTTP и HTTPS.** Cookies имеют `HttpOnly`, `SameSite=Strict`, но без флага `Secure`, чтобы HTTP-тестирование работало. В производстве HTTPS обязателен: сам Nginx должен принудительно перенаправлять HTTP на HTTPS, а прямой HTTP-доступ к Python-порту должен быть закрыт. Без шифрования cookie может быть перехвачена в сети.

Поставьте `client_max_body_size 64k` на административный location и **не кешируйте** HTML/API на Cloudflare/Beget/других CDN. Для примера, если ваш `main.py` слушает `127.0.0.1:3322`:

```nginx
location ^~ /get-info-api/adm {
    client_max_body_size 64k;
    proxy_pass http://127.0.0.1:3322;
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto https;
    proxy_cache off;
    proxy_no_cache 1;
    proxy_cache_bypass 1;
    add_header Cache-Control "private, no-store" always;
}

# Админ-панель использует общую статику приложения по /static/.
# Если /static/ уже проксируется на FastAPI, второй блок не нужен.
location ^~ /static/ {
    proxy_pass http://127.0.0.1:3322;
    proxy_set_header Host $host;
}
```

Все входы `/<SUB>/...` (включая `/get-info-api/adm`) должны попадать **на тот же FastAPI**, а не в отдельный статический сайт. Если сайт расположен за Beget CDN и тот принудительно кеширует ответы, **исключите административный URL из CDN или выделите отдельный DNS-only поддомен без CDN**. Настройка `Cache-Control: no-store` сама по себе не заставляет CDN выполнять правило.

**Ограничьте доступ к HTTP-порту Uvicorn извне** (localhost или firewall). Основной сервер в исходном коде по-прежнему слушает `0.0.0.0` ради совместимости с вашим развёртыванием; НЕ публикуйте этот порт в интернете. Для Nginx на той же машине лучше использовать `host="127.0.0.1"` в `uvicorn.Config(...)` и проверить остальные подключения, которым он нужен.

### Реализованные меры

- Только Telegram ID из списка `ADMINS`, проверяемый **во время подтверждения и каждого запроса**.
- Подтверждение только в личном чате с админ-ботом и по явной кнопке.
- Непредсказуемый одноразовый challenge, связанный с `HttpOnly` cookie исходного браузера; challenge expires через 3 минуты.
- Сессия: случайный секрет с 256+ битами энтропии; только SHA-256 секрета хранится в БД; истекает через 6 ч; кнопка выхода отзывает его на сервере.
- Все API состояния `GET` требуют сессию. Любые изменения также требуют отдельный `X-CSRF-Token` и корректный `Origin`. Проверка выполняется **до разбора JSON**.
- Строгая валидация Pydantic: запрещены неизвестные поля/типы, SQL используется только с параметрами, ID инбаундов сверяются с актуальной панелью, правила/fallback и циклы проверяются общим backend.
- `Content-Security-Policy`, `X-Frame-Options: DENY`, `Cache-Control: no-store`, `Referrer-Policy: no-referrer`, отсутствие внешних скриптов.
- Никакого автоматического логина через доступность ссылки подписки; публичный UUID подписки **не** даёт админ-доступ.

Абсолютной гарантии невозможности взлома ни одно программное решение дать не может. Перед интернет-публикацией обязательно проверьте Nginx, firewall, HTTPS, действующий Telegram-бот, ротацию его токена при компрометации и свежие зависимости. Без живой панели, бота и реального reverse proxy проведены **только локальные проверки**.

## Установка

1. Сделайте бэкап `.env`, SQLite (`subserver.db`) и исходного кода. Не заменяйте текущую рабочую БД файлом из архива.
2. Установите/обновите все файлы проекта и зависимости по `requirements.txt`, без замены `.env`.
3. Убедитесь, что `.env`: `SUB=get-info-api`, `ADMINS=<числовые ID>`, `BOT_TOKEN=<токен админ-бота>`.
4. Перезапустите Python-сервис и служебного бота (бот в текущей архитектуре запускается из `main.py`; **не запускайте второй процесс polling одновременно**).
5. Проверьте `nginx -t`, перезапустите Nginx и откройте `https://домен/get-info-api/adm`.
6. Проверьте неадминистративный Telegram ID, устаревшую ссылку, выход и истечение сессии. Вручную проверьте страницу на телефоне.

**Примечание:** новые правила влияют на **следующее обновление AUTO** в Happ/Incy. Уже загруженный JSON на устройстве не переписывается удалённо.
