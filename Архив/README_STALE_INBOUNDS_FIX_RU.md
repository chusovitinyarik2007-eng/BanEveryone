# Исправление устаревших подключений в веб-панели AUTO

При открытии `/get-info-api/adm` endpoint `/api/state` ранее возвращал полный локальный список `smart_nodes`, включая старые записи после удаления инбаундов в 3x-ui. Кнопка «Обновить список» уже использовала текущий ответ панели, поэтому проблема проявлялась только сразу после входа.

Теперь `/api/state` при каждой загрузке запрашивает `get_inbounds_full()` и вызывает `smart.panel_nodes()` — тот же алгоритм, что и принудительное обновление.

- Только реально возвращённые панелью ID показываются в веб-интерфейсе.
- При переименовании инбаунда сохраняется его ID и состав назначенных пулов; обновляется отображаемое имя.
- Удалённые инбаунды не отображаются. Исторические записи остаются в SQLite для совместимости и резервных копий, но никогда не используются для отображения актуального списка.
- Если панель недоступна, `/api/state` возвращает HTTP 502 без показа устаревшего списка (вместо ложного успеха).
- Состав пулов AUTO не объединяется автоматически, все назначения остаются ручными.

Установка: сохранить резервную копию SQLite, заменить файлы из ZIP, перезапустить Python-сервис. Базу данных мигрировать не требуется.

Добавлены два регрессионных теста: переименование + удаление при первичной загрузке и ошибка обращения к панели без отображения устаревших подключений.
