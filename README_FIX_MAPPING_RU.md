# Исправление AUTO: неверное объединение серверов в балансировщиках

В старой версии `link_profiles_to_inbounds()` могла связать несколько профилей с одним ID инбаунда, если совпадали протокол и порт (обычно `vless:443`). Затем `remember()` восстанавливала связи из устаревших имён/aliases. Из-за этого разные пулы получали одинаковые списки серверов.

## Что исправлено

- Связывание выполняется только если **название профиля и инбаунда совпадает однозначно**, либо если пара `(protocol, port)` уникальна **одновременно у профилей и у инбаундов**. При неоднозначности ассоциация не создаётся.
- Несколько отдельных профилей не могут получить один и тот же ID инбаунда автоматически.
- При обновлении текущие привязки пересчитываются, старые endpoint-only привязки не используются.
- `remember()` больше не создаёт привязки из устаревших aliases.
- При обновлении списка панельных инбаундов больше не переносит назначения пулов по совпадению старых названий.
- Состав каждого балансировщика определяется **только** полем `smart_nodes.pools`; автоматического объединения пулов нет.

## Важная граница

Если несколько профилей выглядят одинаково и нельзя однозначно отличить их от записей панели, они **не попадут в AUTO**, пока не будет достоверного сопоставления. Это безопаснее, чем направлять трафик в чужой балансировщик. После сброса назначений сначала переназначьте нужные серверы и обновите подписку.

## Установка

1. Остановите Python-сервис подписки и боты, которые работают с SQLite.
2. Скопируйте реальный `subserver.db` в резервную копию.
3. Обновите файлы проекта **без перезаписи существующих `.db` и `.env`**.
4. Выполните SQL-файл `RESET_AUTO_SERVER_ASSOCIATIONS.sql` **на реальной базе**: `sqlite3 /путь/к/subserver.db < RESET_AUTO_SERVER_ASSOCIATIONS.sql`.
5. Запустите сервисы. В веб-панели AUTO обновите список подключений и отметьте серверы каждого балансировщика вручную.
6. Откройте подписку в Happ/Incy, обновите её и убедитесь, что в `routing.balancers[].selector` у каждого балансировщика ровно выбранные вами серверы.

**Сброс не затрагивает**: настройки самих балансировщиков (стратегии, fallback, приоритеты, доменные/IP-правила), RU→DIRECT, интервал проверок, пользователей и ключи. Он удаляет **все старые назначения серверов**, чтобы вы могли назначить их заново.

Если на всех профилях одинаковый внешний порт 443, а названия профилей не совпадают с названиями инбаундов, система намеренно не угадывает соответствия и может не создавать AUTO. Для точной привязки нужны уникальные названия, видимые в панели и в JSON подписки, либо отдельная явная привязка профиля к ID (последнее пока не реализовано).
